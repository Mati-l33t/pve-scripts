## Notes

<div class="warn-callout">
  <i class="fas fa-exclamation-triangle"></i>
  <div>There is no default account. Create one at http://[IP]:8080/auth/signup. Sign-up is open to anyone who can reach the port, so once your accounts exist set ENABLE_INTERNAL_SIGNUP=false in /opt/notemark_data/.env and run systemctl restart notemark.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>PUBLIC_URL in /opt/notemark_data/.env is set to the container IP. It must be the address you open Note Mark at, without a trailing slash. Change it when the IP changes or when Note Mark sits behind a reverse proxy or domain, then run systemctl restart notemark. Upstream recommends a reverse proxy with HTTPS and rate limiting on /api/auth/*. Copy to clipboard and installing the app as a PWA only work over HTTPS.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>Notes are stored as plain Markdown files in /opt/notemark_data/notes, and users plus the folder cache in /opt/notemark_data/db.sqlite. Back up the whole /opt/notemark_data directory. If you change note files outside Note Mark, run the clear-cache command and restart the service.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>The CLI (user add, set-password, clear-cache, clean) needs the service environment: set -a; . /opt/notemark_data/.env; set +a; /opt/notemark/note-mark --help</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>Install and every update build the Go backend and the Rust/WebAssembly + SolidJS frontend from source. That takes about 9 minutes on 2 cores and needs around 1 GB of RAM. The running server uses only a few dozen MB.</div>
</div>
