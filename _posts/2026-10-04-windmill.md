## Notes

<div class="warn-callout">
  <i class="fas fa-exclamation-triangle"></i>
  <div>Log in with admin@windmill.dev / changeme right after the install. Windmill then asks for a new superadmin account, which replaces the default one. Until you do that, anyone who reaches port 8000 can log in with the default credentials.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>Webhook URLs, OAuth redirects and links in emails are built from BASE_URL in /opt/windmill_data/.env, which points at the container IP. Change it when the IP changes or Windmill sits behind a reverse proxy or domain, then run systemctl restart windmill. A Base URL set in the instance settings takes precedence.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>Python (through uv, which downloads the Python version on first use), TypeScript on Bun, Bash, DuckDB and SQL scripts run out of the box. The other languages the editor offers (TypeScript on Deno, Go, PHP, PowerShell, Rust, C#, Java, Ansible and more) need their runtime installed in the container first.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>Server and worker share one process with a single worker, so jobs run one at a time. For parallel jobs, run more Windmill processes with MODE=worker against the same database.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>The windmill database role has no CREATEDB or CREATEROLE privilege, so the Custom instance database option for Data Tables and DuckLake fails with permission denied. Point Data Tables at a PostgreSQL resource instead.</div>
</div>
