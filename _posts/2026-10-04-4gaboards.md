## Notes

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>The admin password is generated during install and stored as DEFAULT_ADMIN_PASSWORD in /opt/4gaboards_data/.env. Log in with admin (or admin@4gaboards.local) and change the password and email under Settings. The DEFAULT_ADMIN_* values are only read when the database is first created, so editing them later changes nothing.</div>
</div>

<div class="warn-callout">
  <i class="fas fa-exclamation-triangle"></i>
  <div>User registration is open, which is the upstream default: anyone who reaches the port can create an account. Turn off User Registration in Settings > Instance Settings if that is not wanted.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>BASE_URL in /opt/4gaboards_data/.env points at the container IP, and realtime updates only accept that origin. Change it when the IP changes or 4ga Boards sits behind a reverse proxy or domain (set TRUST_PROXY=1 behind a proxy), then run systemctl restart 4gaboards.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>On every start the server registers itself with notifications.4gaboards.com (instance URL, public IP) to receive release and security notices, and logs retry warnings while that host is unreachable. SYSTEM_NOTIFICATIONS_DISABLED=true in the .env opts out of the notices, but the registration request is still sent.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>Install and every update build the web client from source, which peaks at about 2.4 GB of RAM. The running server needs around 300 MB, so the RAM can be lowered after the install and raised again before an update.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>Attachments, avatars and project backgrounds are kept in /opt/4gaboards_data. Back that directory up together with the PostgreSQL database.</div>
</div>
