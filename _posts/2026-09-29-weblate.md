## Notes

<div class="warn-callout">
  <i class="fas fa-exclamation-triangle"></i>
  <div>The admin password is generated at install and stored as WEBLATE_ADMIN_PASSWORD in /opt/weblate_data/weblate.env. Weblate does not read that value, so change the password from your profile afterwards, or reset it with <code>weblate createadmin --update</code>.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>Settings come from upstream's environment-driven weblate.settings_docker: add WEBLATE_* variables from the Docker documentation to /opt/weblate_data/weblate.env (for example WEBLATE_EMAIL_HOST for outgoing mail, or WEBLATE_SITE_DOMAIN and WEBLATE_ENABLE_HTTPS=1 behind an HTTPS proxy), then run <code>systemctl restart weblate weblate-celery</code>. Python-level overrides go in /opt/weblate_data/settings-override.py.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>No mail server is configured, so registration and notification e-mails fail until WEBLATE_EMAIL_HOST is set.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>Management commands need the environment loaded: <code>set -a; . /opt/weblate_data/weblate.env; set +a; /opt/weblate/.venv/bin/weblate <command></code>.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>Celery runs two worker processes (--concurrency=2 in weblate-celery.service). Raise it together with CPU and RAM if Weblate reports long task queues.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>Repositories, uploads and the secret key live in /opt/weblate_data. Back it up together with the PostgreSQL database.</div>
</div>
