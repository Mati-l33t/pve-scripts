## Notes

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>On first start llama-server downloads the model set in LLAMA_ARG_HF_REPO (default: ggml-org/gemma-3-1b-it-GGUF, roughly 800 MB) into /opt/llama-cpp_data/models, so the container is usable straight away. Swap it for any GGUF repo, or point LLAMA_ARG_MODEL at a local file, then restart.</div>
</div>

<div class="warn-callout">
  <i class="fas fa-exclamation-triangle"></i>
  <div>The web UI and the OpenAI-compatible API share port 8080: /v1/chat/completions, /v1/models and friends. There is no authentication unless an API key is set - supply one at install time or set LLAMA_ARG_API_KEY in /opt/llama-cpp.env.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>The build variant is chosen at install time: cpu, vulkan or rocm, or auto to follow the passed-through GPU. Upstream publishes no Linux CUDA build, so an NVIDIA card is served by the vulkan build and needs NVIDIA's Vulkan driver in the container. The choice is remembered in /opt/llama-cpp_data/.backend so updates keep it.</div>
</div>

<div class="info-callout">
  <i class="fas fa-info-circle"></i>
  <div>RAM is the limiting factor: the model must fit alongside the KV cache. 8 GB comfortably runs models up to roughly 7B at Q4. Raise LLAMA_ARG_CTX_SIZE only if you have headroom.</div>
</div>
